# StreamForge

StreamForge — экспериментальная библиотека на Go для выполнения MapReduce-задач в одном процессе. Она разбивает входные данные на map-задачи, группирует промежуточные значения по ключу и запускает reduce-задачи в пуле goroutine.

Сейчас библиотека рассчитана на простые задачи обработки данных. Она не запускает вычисления на нескольких машинах и не сохраняет промежуточные результаты на диск.

## Требования

- Go версии 1.26.6 или новее — версия, указанная в `go.mod`.
- Сторонние Go-модули проекту не нужны.

## Установка

В проекте, который использует StreamForge, добавьте модуль:

```sh
go get github.com/bug00n/StreamForge
```

## Пример

Встроенный пример подсчёта слов находится в `engine/fixtures_wc`:

```go
package main

import (
	"fmt"

	"github.com/bug00n/StreamForge/engine"
	"github.com/bug00n/StreamForge/engine/fixtures_wc"
)

func main() {
	eng := engine.CreateEngine[string, fixtures.Key, int, int](
		4, // map workers
		2, // reduce workers
		3, // shuffle partitions
	)
	defer eng.Close()

	view, err := eng.Submit(
		fixtures.Data("go map reduce\ngo map"),
		fixtures.Mapper,
		fixtures.Reducer,
	)
	if err != nil {
		panic(err)
	}

	<-view.Done()
	if err := view.Err(); err != nil {
		panic(err)
	}
	fmt.Println(view.Load())
}
```

Результат содержит `go: 2`, `map: 2` и `reduce: 1`. Порядок элементов в напечатанной map не гарантируется.

## Как работает обработка

1. Тип входных данных реализует `contracts.Data[T]`: метод `Split()` возвращает срез элементов типа `T`.
2. Движок делит этот срез на map-задачи. Сейчас одна задача получает до 500 элементов.
3. Mapper принимает один элемент и возвращает срез пар `contracts.Result[K, V]` и ошибку.
4. Движок отправляет значения одного ключа в одну shuffle-партицию по результату `Key.Hash()`.
5. Для каждой shuffle-партиции создаётся reduce-задача. Reduce workers обрабатывают эти задачи параллельно.
6. После успешного завершения всех reduce-задач канал `Done()` закрывается, а `Load()` возвращает результаты. При ошибке callback-ов job завершается со статусом `JobFailed` и тем же закрытым каналом.

Число shuffle-партиций задаёт группировку ключей и не обязано совпадать с числом reduce workers. Если партиций больше, чем workers, лишние задачи ждут в очереди.

## Настройка движка

```go
eng := engine.CreateEngine[T, K, V, R](mappersCnt, reducersCnt, shufflePartitionsCnt)
```

- `mappersCnt` — число map workers.
- `reducersCnt` — число reduce workers.
- `shufflePartitionsCnt` — число партиций, в которые распределяются ключи.

Все три значения должны быть положительными.

## Требования к типам и функциям

- `T` — тип одного элемента `Data[T]`, возвращаемого `Data[T].Split()`.
- `K` должен быть сравнимым типом и реализовывать `Hash() uint32`.
- Mapper имеет сигнатуру `func(T) ([]contracts.Result[K, V], error)`.
- Reducer имеет сигнатуру `func(K, []V) (R, error)`.
- `V` и `R` могут быть любыми Go-типами.

Если mapper или reducer возвращает ошибку, job получает статус `JobFailed`, а `Done()` закрывается. Причину можно получить через `view.Err()`. Другие задачи этой job проверяют её состояние перед следующим вызовом callback и прекращают обработку после ошибки. Уже выполняющийся callback нельзя прервать.a

Mapper и reducer могут вызываться параллельно несколькими workers, в том числе для разных задач одного движка. Если функции обращаются к общему изменяемому состоянию, синхронизацию должен обеспечить вызывающий код.

## Получение результатов

`Submit` возвращает `JobViewer[T, K, V, R]`. После закрытия `Done()` проверьте `Err()`: `nil` означает успешное выполнение, иначе там находится ошибка mapper или reducer. Текущий статус job можно получить через `Status()`.

```go
view, err := eng.Submit(data, mapper, reducer)
if err != nil {
	panic(err)
}
<-view.Done()

if err := view.Err(); err != nil {
	panic(err)
}

results := view.Load()
```

`Done()` возвращает канал завершения. `Load()` возвращает `nil`, пока job не завершилась или если она завершилась с ошибкой; после успешного завершения он делает только поверхностную копию внешней map. Значения типа `R` и вложенные данные не копируются: если `R` содержит срез, map или указатель, их изменение через результат `Load()` может изменить объект, на который ссылается результат job. Go не гарантирует порядок обхода map.

`Close()` прекращает приём новых jobs, обрабатывает уже принятые задачи и дожидается остановки workers. Вызов `Submit()` после `Close()` возвращает `ErrEngineClosed`. Отменить или ограничить по времени уже выполняемую задачу нельзя; остальные известные ограничения описаны в [KNOWN_ISSUES.md](KNOWN_ISSUES.md).
